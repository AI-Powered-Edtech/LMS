# User Personas & Journey Mapping — EduSync LMS

> Dokumen ini berisi 5 user persona detail untuk konteks sekolah Indonesia beserta user journey map masing-masing.
> Terakhir diperbarui: Maret 2026

---

## Persona 1: Bu Ratna — Guru SMP/SMA yang Baru Mengadopsi LMS

### Demografi & Profil

- **Usia:** 38 tahun
- **Jabatan:** Guru Matematika SMP Negeri, wali kelas 8
- **Lokasi:** Kota kabupaten di Jawa Tengah
- **Pendidikan:** S1 Pendidikan Matematika
- **Gaji:** Rp 4-6 juta/bulan (PNS golongan III)
- **Tech Literacy:** Rendah-Menengah — bisa pakai WhatsApp, YouTube, dan Google; belum pernah pakai LMS
- **Device Utama:** Smartphone Android (mid-range), laptop lama (dibagi dengan keluarga)
- **Koneksi Internet:** WiFi sekolah (sering lambat), paket data 4G di rumah (kuota terbatas)

### Goals

- Mengurangi beban administratif (absensi, input nilai manual ke rapor)
- Memantau progress siswa tanpa harus menunggu ujian semester
- Membuat pembelajaran lebih menarik agar siswa tidak bosan
- Memenuhi tuntutan digitalisasi dari kepala sekolah dan dinas pendidikan
- Meningkatkan kompetensi digital untuk kenaikan pangkat

### Frustrations

- Banyak platform teknologi yang terlalu rumit dan full bahasa Inggris
- Waktu terbatas — mengajar 24 jam/minggu plus tugas administrasi
- Siswa lebih tertarik main HP daripada belajar
- Tidak ada yang mengajari cara pakai teknologi di sekolah
- Sudah pernah coba Google Classroom tapi berhenti karena fitur terbatas dan siswa tidak aktif

### Daily Workflow

- 06:00 — Berangkat ke sekolah
- 07:00-13:00 — Mengajar 5-6 jam pelajaran
- 13:00-14:00 — Istirahat, cek WhatsApp group kelas dan guru
- 14:00-15:30 — Koreksi tugas, input nilai, rapat guru
- 19:00-21:00 — Persiapan materi besok di rumah (via HP)

### User Journey Map

#### Stage 1: Discovery (Minggu 1)

- **Touchpoint:** Kepala sekolah mengumumkan sekolah akan pakai EduSync
- **Action:** Bu Ratna ikut sosialisasi/pelatihan dari tim EduSync
- **Feeling:** Cemas, takut tidak bisa
- **Pain Points:** Terminologi asing, takut salah klik, malu bertanya
- **Opportunity:** Onboarding video dalam Bahasa Indonesia yang sederhana; walkthrough step-by-step; buddy system dengan guru yang lebih tech-savvy

#### Stage 2: Onboarding (Minggu 2-3)

- **Touchpoint:** Login pertama kali, melihat dashboard guru
- **Action:** Mencoba membuat kursus pertama, menambahkan siswa
- **Feeling:** Overwhelmed tapi penasaran
- **Pain Points:** Terlalu banyak menu; tidak tahu harus mulai dari mana; kursus kosong terasa membingungkan
- **Opportunity:** Guided setup wizard ("Buat kursus pertama Anda dalam 5 menit"); template kursus siap pakai sesuai kurikulum; empty state yang informatif

#### Stage 3: Daily Use (Bulan 1-3)

- **Touchpoint:** Menggunakan EduSync untuk tugas dan quiz harian
- **Action:** Upload materi, buat quiz sederhana, lihat nilai siswa
- **Feeling:** Mulai nyaman, tapi masih sering bingung fitur advanced
- **Pain Points:** Membuat quiz memakan waktu; siswa lupa login; tidak tahu cara baca analytics
- **Opportunity:** AI content generation untuk soal; reminder otomatis ke siswa; tooltip penjelasan pada analytics; quick-create quiz dari question bank

#### Stage 4: Advanced Use (Bulan 3-6)

- **Touchpoint:** Mulai eksplor fitur analytics, gamification, AI tutor
- **Action:** Lihat struggle detection, setup badges untuk motivasi siswa
- **Feeling:** Excited melihat data progress siswa secara real-time
- **Pain Points:** Ingin share insight ke orang tua tapi tidak ada portal; belum bisa generate rapor langsung
- **Opportunity:** Parent portal; rapor digital; export analytics ke PDF untuk rapat orang tua; template laporan progress

## Persona 2: Rafi — Siswa SMA Tech-Savvy

### Demografi & Profil

- **Usia:** 16 tahun
- **Kelas:** SMA kelas 11 IPA
- **Lokasi:** Kota besar (Surabaya)
- **Tech Literacy:** Tinggi — aktif di social media, gaming, familiar dengan berbagai app
- **Device Utama:** Smartphone Android (mid-range, layar 6.5"), jarang akses laptop
- **Koneksi Internet:** WiFi di rumah, paket data 4G unlimited
- **Screen Time:** 6-8 jam/hari (mayoritas social media dan gaming)

### Goals

- Mendapat nilai bagus tanpa harus belajar terlalu lama
- Tahu persis di mana kelemahannya agar bisa fokus belajar
- Belajar dengan cara yang interaktif dan tidak membosankan
- Bersaing dengan teman-teman (kompetitif)
- Akses materi dan tugas kapan saja dari HP

### Frustrations

- Platform belajar yang loading lama atau tidak mobile-friendly
- UI yang terlihat "jadul" atau tidak menarik
- Harus bolak-balik antara banyak platform (Google Classroom, WhatsApp, website sekolah)
- Tidak ada feedback instan — harus menunggu guru koreksi manual
- Belajar terasa monoton — baca teks panjang tanpa interaksi

### Daily Workflow

- 06:00-07:00 — Persiapan sekolah, cek HP (Instagram, TikTok)
- 07:00-14:00 — Di sekolah, sesekali cek HP saat istirahat
- 14:00-16:00 — Pulang, main game atau nonton YouTube
- 19:00-21:00 — Kerjakan PR dan belajar (di HP, sambil chat WhatsApp)
- 21:00-23:00 — Social media, gaming

### User Journey Map

#### Stage 1: Discovery

- **Touchpoint:** Guru mengumumkan kelas pakai EduSync, diberi join code
- **Action:** Download/buka di browser HP, register, join kelas
- **Feeling:** Skeptis ("pasti boring lagi")
- **Pain Points:** Jika proses registrasi berbelit; jika web tidak responsive di HP
- **Opportunity:** One-tap join via link/QR code; mobile-first landing page; langsung bisa lihat apa yang menarik (leaderboard, badges)

#### Stage 2: Onboarding

- **Touchpoint:** Pertama kali masuk dashboard siswa
- **Action:** Lihat-lihat kursus, coba quiz pertama
- **Feeling:** Tertarik jika ada gamifikasi, bosan jika tampilan standar
- **Pain Points:** Dashboard terlalu banyak teks; tidak jelas apa yang harus dilakukan pertama
- **Opportunity:** Gamified onboarding ("Selesaikan misi pertamamu, dapatkan 50 XP!"); visual progress bar; dashboard yang clean dan action-oriented

#### Stage 3: Daily Use

- **Touchpoint:** Buka EduSync 2-3x sehari dari HP untuk cek tugas dan quiz
- **Action:** Kerjakan quiz, lihat nilai, cek leaderboard, belajar dari lesson
- **Feeling:** Engaged jika ada kompetisi dan reward; bosan jika hanya text-based
- **Pain Points:** Loading lambat di koneksi buruk; tidak ada push notification untuk deadline; quiz tidak bisa pause-resume
- **Opportunity:** PWA dengan offline cache; push notif deadline H-1 dan H-hari; quiz autosave (sudah ada!); streak reminder; social features (like, comment)

#### Stage 4: Advanced Use

- **Touchpoint:** Aktif di leaderboard, mengejar badges, pakai AI Tutor
- **Action:** Tanya AI Tutor saat stuck di soal; review quiz yang salah; ajak teman compete
- **Feeling:** Ketagihan jika reward system meaningful; frustrasi jika stuck tanpa bantuan
- **Pain Points:** AI Tutor tidak selalu akurat; tidak bisa share achievement ke teman di luar platform; tidak ada team challenge
- **Opportunity:** Share badges ke social media; team/class challenge; AI Tutor yang makin pintar; personalized learning path

## Persona 3: Pak Hendra — Admin Sekolah / Wakil Kepala Sekolah

### Demografi & Profil

- **Usia:** 45 tahun
- **Jabatan:** Wakil Kepala Sekolah Bidang Kurikulum, SMA Swasta
- **Lokasi:** Kota medium (Malang)
- **Pendidikan:** S2 Manajemen Pendidikan
- **Tech Literacy:** Menengah — bisa pakai Excel, email, Zoom; familiar dengan Dapodik
- **Device Utama:** Laptop (kerja), smartphone (komunikasi)
- **Koneksi Internet:** WiFi sekolah (dedicated), WiFi rumah

### Goals

- Digitalisasi proses KBM tanpa menambah beban guru secara signifikan
- Memiliki data terpusat untuk reporting ke kepala sekolah dan dinas pendidikan
- Mengurangi pekerjaan manual (absensi kertas, rekap nilai di Excel)
- Memastikan semua guru dan siswa aktif menggunakan platform
- Menjaga kualitas pembelajaran terstandar di semua kelas

### Frustrations

- Guru-guru senior resistensi terhadap teknologi
- Banyak platform yang harus dikelola (Dapodik, e-Rapor, Google Classroom, spreadsheet)
- Data tersebar di mana-mana — sulit mendapat gambaran menyeluruh
- Budget IT sekolah terbatas
- Tidak ada satu platform yang cover semua kebutuhan sekolah

### Daily Workflow

- 07:00-08:00 — Briefing guru, cek kehadiran
- 08:00-12:00 — Supervisi KBM, handle administrasi
- 12:00-13:00 — Istirahat, update data Dapodik/e-Rapor
- 13:00-15:00 — Rapat, evaluasi program, perencanaan
- 19:00-21:00 — Rekap data di laptop, persiapan laporan

### User Journey Map

#### Stage 1: Discovery & Evaluation

- **Touchpoint:** Mencari solusi LMS untuk sekolah, baca review, minta demo
- **Action:** Bandingkan fitur dan harga beberapa LMS, presentasi ke kepala sekolah
- **Feeling:** Hati-hati, butuh jaminan ROI
- **Pain Points:** Sulit membandingkan platform karena fitur beda-beda; khawatir guru tidak mau pakai; budget terbatas
- **Opportunity:** Free trial untuk sekolah; ROI calculator; case study sekolah Indonesia yang sudah pakai; pricing transparan

#### Stage 2: Onboarding & Setup

- **Touchpoint:** Admin dashboard, setup sekolah
- **Action:** Buat kelas, import data siswa, assign guru ke kelas
- **Feeling:** Butuh proses cepat dan minim error
- **Pain Points:** Import data siswa dari Excel sering error; setup manual per kelas memakan waktu; perlu training guru satu per satu
- **Opportunity:** Bulk import siswa dari Excel/CSV; template setup sekolah; admin training video; auto-assign guru berdasarkan jadwal

#### Stage 3: Daily Use

- **Touchpoint:** Admin dashboard, monitoring guru dan siswa
- **Action:** Cek teacher activity, lihat class-wide metrics, handle moderation
- **Feeling:** Butuh overview cepat tanpa harus drill-down
- **Pain Points:** Tidak bisa lihat guru mana yang aktif/tidak; reporting masih harus manual ke dinas; moderation report lambat
- **Opportunity:** Teacher activity dashboard; automated weekly report; moderation queue yang efisien; export ke format Dapodik/e-Rapor

#### Stage 4: Advanced Use

- **Touchpoint:** Analytics sekolah, reporting semester
- **Action:** Generate laporan untuk rapat komite, evaluasi efektivitas LMS
- **Feeling:** Butuh data yang bisa "berbicara" ke stakeholder
- **Pain Points:** Tidak bisa compare antar kelas/guru secara visual; tidak ada rapor digital terintegrasi; data attendance dan akademik terpisah
- **Opportunity:** School-wide analytics dashboard; automated semester report; rapor digital generation; benchmark antar kelas; compliance reporting

## Persona 4: Ibu Sari — Orang Tua Siswa (BELUM ADA DI EDUSYNC)

### Demografi & Profil

- **Usia:** 42 tahun
- **Pekerjaan:** Karyawan swasta (admin kantor)
- **Lokasi:** Pinggiran kota besar (Bekasi)
- **Anak:** 1 anak SMP kelas 8
- **Pendidikan:** D3 Akuntansi
- **Tech Literacy:** Rendah-Menengah — WhatsApp lancar, sesekali buka Instagram, bisa Google
- **Device Utama:** Smartphone Android (utama dan satu-satunya device)
- **Koneksi Internet:** Paket data 4G (hemat kuota)

### Goals

- Tahu apakah anak rajin mengerjakan tugas dan masuk kelas
- Melihat nilai anak secara real-time, tidak menunggu rapor semester
- Bisa komunikasi langsung dengan guru tanpa harus datang ke sekolah
- Memastikan anak belajar di HP, bukan main game
- Terlibat aktif dalam pendidikan anak meski sibuk bekerja

### Frustrations

- Informasi dari sekolah datang lewat WhatsApp group yang ramai dan sulit dicari
- Anak bilang "sudah mengerjakan PR" tapi tidak bisa diverifikasi
- Harus menunggu mid-semester atau semester untuk tahu nilai anak
- Tidak paham platform yang digunakan anak di sekolah
- Ingin bantu tapi tidak tahu caranya

### Daily Workflow

- 06:00-07:00 — Antar anak sekolah
- 07:00-17:00 — Kerja di kantor
- 17:00-19:00 — Pulang, masak, urusan rumah
- 19:00-20:00 — Tanya anak soal sekolah (biasanya dijawab "biasa aja")
- 20:00-22:00 — Cek WhatsApp group sekolah, scrolling social media

### User Journey Map (PROPOSED)

#### Stage 1: Discovery & Registration

- **Touchpoint:** Dapat undangan dari sekolah (via WhatsApp/surat) untuk daftar portal orang tua
- **Action:** Klik link, register dengan nomor HP, verifikasi, link ke profil anak
- **Feeling:** Penasaran tapi khawatir ribet
- **Pain Points:** Proses registrasi yang terlalu banyak langkah; lupa password; bingung cara link ke anak
- **Opportunity:** Register via WhatsApp atau nomor HP (OTP); auto-link anak jika sudah di database sekolah; UI super sederhana khusus orang tua; tutorial 30 detik

#### Stage 2: Onboarding

- **Touchpoint:** Dashboard orang tua (mobile-first)
- **Action:** Lihat overview progress anak, cek nilai terbaru
- **Feeling:** Senang bisa lihat data, tapi butuh penjelasan
- **Pain Points:** Terminologi LMS membingungkan; terlalu banyak angka tanpa konteks; tidak tahu apa itu "XP" atau "streak"
- **Opportunity:** Dashboard sederhana dengan bahasa awam ("Anak Anda mengerjakan 8 dari 10 tugas minggu ini"); visual progress (bintang, emoji); tooltip penjelasan

#### Stage 3: Daily Use

- **Touchpoint:** Notifikasi WhatsApp/push notification harian
- **Action:** Cek apakah anak sudah submit tugas, lihat nilai quiz terbaru
- **Feeling:** Tenang jika semua hijau, khawatir jika ada merah
- **Pain Points:** Terlalu banyak notifikasi membuat kewalahan; tidak bisa reply ke guru langsung; data kehadiran tidak terupdate
- **Opportunity:** Digest harian (1 notif rangkuman sore hari); traffic light system (hijau/kuning/merah); quick reply ke guru; kehadiran real-time

#### Stage 4: Engagement Mendalam

- **Touchpoint:** Laporan progress bulanan, komunikasi dengan guru
- **Action:** Review progress bulanan, diskusi dengan guru via platform, lihat achievement anak
- **Feeling:** Merasa terlibat dan bisa mendukung anak
- **Pain Points:** Sulit scheduling pertemuan dengan guru; tidak tahu cara membantu anak yang nilainya turun
- **Opportunity:** Progress report otomatis bulanan via WhatsApp; tips belajar untuk orang tua; appointment booking dengan guru; celebration saat anak achieve sesuatu

## Persona 5: Bapak Dr. Widodo — Kepala Sekolah / Decision Maker

### Demografi & Profil

- **Usia:** 52 tahun
- **Jabatan:** Kepala SMA Swasta menengah (600 siswa, 40 guru)
- **Lokasi:** Kota besar (Bandung)
- **Pendidikan:** S2 Manajemen Pendidikan, sertifikasi kepala sekolah
- **Tech Literacy:** Menengah — pakai laptop untuk email dan dokumen, delegate urusan teknis
- **Device Utama:** Laptop (utama), smartphone (WhatsApp dan email)
- **Koneksi Internet:** WiFi sekolah, WiFi rumah

### Goals

- Meningkatkan mutu dan reputasi sekolah melalui inovasi digital
- Mendapat data konkret untuk laporan ke yayasan dan dinas pendidikan
- ROI yang jelas dari investasi teknologi (peningkatan nilai UN/ANBK, kepuasan ortu)
- Efisiensi operasional sekolah — kurangi paper work, kurangi biaya cetak
- Sekolah bisa bersaing dengan sekolah lain yang sudah digital

### Frustrations

- Investasi teknologi sebelumnya sering gagal karena guru tidak mau pakai
- Sulit mengukur apakah platform digital benar-benar meningkatkan kualitas belajar
- Vendor teknologi sering menjanjikan banyak tapi support setelah implementasi buruk
- Budget terbatas — harus pilih antara banyak kebutuhan sekolah
- Tekanan dari yayasan untuk modernisasi tapi tanpa tambahan budget signifikan

### Decision-Making Workflow

- **Information Gathering:** Minta wakasek kurikulum riset opsi LMS
- **Evaluation:** Review presentasi vendor, minta demo, cek referensi sekolah lain
- **Decision Criteria:** Harga terjangkau, mudah dipakai guru, ada fitur reporting, support bahasa Indonesia, vendor bisa di-reach
- **Approval:** Presentasi ke yayasan dengan cost-benefit analysis
- **Implementation:** Delegasi ke wakasek kurikulum dan tim IT sekolah

### User Journey Map

#### Stage 1: Awareness & Evaluation

- **Touchpoint:** Rekomendasi dari kepala sekolah lain, iklan di seminar pendidikan, presentasi vendor
- **Action:** Minta wakasek evaluasi, lihat demo singkat, bandingkan harga
- **Feeling:** Pragmatis — butuh bukti, bukan janji
- **Pain Points:** Demo vendor selalu terlihat bagus tapi kenyataan berbeda; sulit bandingkan apple-to-apple; tidak punya waktu untuk trial mendalam
- **Opportunity:** Case study ROI dari sekolah serupa; executive summary 1 halaman; free pilot 1 semester untuk 2-3 kelas; pricing yang transparan dan predictable

#### Stage 2: Decision & Procurement

- **Touchpoint:** Proposal dari vendor, presentasi ke yayasan
- **Action:** Negosiasi harga, tentukan scope implementasi, tanda tangan kontrak
- **Feeling:** Butuh reassurance — jaminan support dan training
- **Pain Points:** Kontrak yang rumit; tidak jelas apa yang termasuk dan tidak; hidden cost
- **Opportunity:** Paket all-inclusive (platform + training + support); pricing per sekolah (bukan per siswa); SLA yang jelas; money-back guarantee periode tertentu

#### Stage 3: Implementation & Monitoring

- **Touchpoint:** Laporan dari wakasek kurikulum, dashboard admin (via delegation)
- **Action:** Review laporan bulanan penggunaan LMS, cek apakah guru aktif pakai
- **Feeling:** Khawatir jika adopsi rendah; lega jika data menunjukkan progress
- **Pain Points:** Laporan terlalu teknis; tidak bisa lihat ROI secara langsung; guru mengeluh platform sulit
- **Opportunity:** Executive dashboard — 1 halaman overview (adopsi guru, rata-rata nilai, engagement siswa); monthly ROI report; adoption leaderboard antar guru

#### Stage 4: Evaluation & Renewal

- **Touchpoint:** Evaluasi akhir semester, keputusan perpanjangan kontrak
- **Action:** Bandingkan data sebelum dan sesudah LMS, survey kepuasan guru dan ortu
- **Feeling:** Butuh amunisi data untuk justify perpanjangan ke yayasan
- **Pain Points:** Data sebelum LMS tidak tersedia untuk perbandingan; sulit isolasi dampak LMS dari faktor lain
- **Opportunity:** Before-after analytics otomatis; survey kepuasan built-in; benchmark dengan sekolah serupa; certification/award untuk sekolah digital

## Ringkasan Cross-Persona Insights

### Pain Points yang Sama di Semua Persona

1. **Kompleksitas Platform** — Semua persona (kecuali Rafi) takut platform terlalu rumit
2. **Mobile-First Necessity** — 4 dari 5 persona utamanya menggunakan smartphone
3. **Komunikasi Terfragmentasi** — Semua bergantung pada WhatsApp untuk komunikasi sekolah
4. **Data Tersebar** — Admin dan kepala sekolah frustrasi data di banyak tempat
5. **Bahasa** — UI bahasa Inggris menjadi barrier untuk adopsi

### Implikasi untuk EduSync

| Insight                       | Implikasi Produk                                           | Prioritas |
| ----------------------------- | ---------------------------------------------------------- | --------- |
| Guru butuh kesederhanaan      | Simplify onboarding, template siap pakai, guided workflows | P0        |
| Siswa butuh engagement        | Gamification yang lebih sosial, mobile-first UX            | P0        |
| Orang tua butuh transparansi  | Parent portal dengan dashboard sederhana                   | P0        |
| Admin butuh efisiensi         | Bulk operations, automated reporting, integration          | P1        |
| Kepsek butuh ROI data         | Executive dashboard, before-after analytics                | P1        |
| Semua butuh WhatsApp          | WhatsApp notification integration                          | P0        |
| Mobile-first adalah keharusan | PWA atau native app                                        | P0        |
