# Module Consolidation Plan

> Generated by project analysis on 2026-03-31

## Overlapping Modules Identified

### 1. `courses` vs `creator`
- **courses** — handles course listing, enrollment, viewing
- **creator** — handles course creation/editing (BuilderContext)
- **Recommendation:** Keep separate. `creator` is the editor, `courses` is the consumer. Natural separation of concerns.

### 2. `progress` vs `lessons`
- **progress** — tracks student progress, aggregates data (`student_lesson_signals`, progress queries)
- **lessons** — lesson content, viewer, resources
- **Recommendation:** Keep separate. `progress` is data-layer, `lessons` is content-layer. They have different audiences (admin/reports vs students).

### 3. `gradebook` vs `assignments`
- **gradebook** — grading logic, rubrics, CSV export
- **assignments** — assignment creation, submission, review
- **Recommendation:** Keep separate. `gradebook` spans quizzes AND assignments, not just assignments.

### 4. `analytics` vs `dashboards`
- **analytics** — data aggregation, queries, tracking
- **dashboards** — UI dashboard views
- **Recommendation:** Consider merging. `dashboards` is mostly thin UI wrappers over `analytics` queries. Could be `analytics/dashboards/`.

## No Action Needed
The 30-module structure is well-designed. Each module has clear boundaries. The overlaps are intentional (layer separation), not redundant code.
