## Verifikasi yang HARUS Anda lakukan di laptop lain

Sandbox tempat batch ini ditulis tidak bisa run cargo / docker. Gate berikut
**belum dilewati**:

1. **Compile**
   ```sh
   cd edusync-api && cargo build --release
   ```
   Risk areas (saya nulis blind, mungkin ada compile error):
   - `rapor_pdf_handler.rs` — pakai `axum::extract::Path` + `IntoResponse`. Pattern ditiru dari `notification_handlers.rs::generate_pdf_handler`, harusnya OK.
   - `payment_handlers.rs` — `BigDecimal::to_string().parse::<i64>()` mungkin perlu `bigdecimal::ToPrimitive`. Cek deps.
   - `events_worker.rs` — pakai `futures_util::FutureExt::catch_unwind` + `AssertUnwindSafe`. Cek `futures-util` di Cargo.toml api-server (ada).
   - `ai_rate_limit.rs` — pakai `thiserror::Error` di middleware crate; cek deps middleware crate punya `thiserror` (ada per Cargo.toml).
   - `rbac_roles.rs` & `rbac_scope.rs` — pakai sqlx. middleware crate sudah punya sqlx workspace dep.

2. **Apply schema**
   ```sh
   for m in edusync-api/migrations/0{69,70,71,72}_*.sql; do
     psql "$DATABASE_URL" -f "$m"
   done
   ```

3. **Run dev seed**
   ```sh
   ./edusync-api/scripts/reset-dev-school.sh
   ```

4. **Start backend + FE**
   ```sh
   cd edusync-api && ./target/release/api-server &
   ./node_modules/.bin/vite --host &
   ```

5. **Real-backend sweep** (no mocks, per memory):
   ```sh
   npx playwright test tests/e2e/sweep.spec.ts --reporter=line
   npx playwright test tests/e2e/rbac.spec.ts  --reporter=line
   ```
   - `rbac.spec.ts` Acceptance: `unexpected_deny = 0` di matrix output.
   - Sweep: bandingkan ke baseline `.qa-sweep-baseline.json`.

6. **PDF POC**
   ```sh
   node services/pdf-renderer/render.mjs \
     < services/pdf-renderer/samples/rapor-fixture.json > /tmp/out.pdf
   ```
   Butuh `puppeteer-core` di node_modules (belum di-install — `npm i -D puppeteer-core` kalau belum).

   - Login `ortu001@nusantara.dev` → `/app/parent/tagihan` → klik **Bayar**

## Risiko spesifik yang sudah saya tahu

1. **`rapor_pdf_handler.rs` query** — mengasumsikan kolom yang **mungkin belum ada**:
   - `tenants.address`, `tenants.npsn`
   - `profiles.nis`, `profiles.nisn`
   - `rapor_kurmer.fase`, `rapor_kurmer.subjects_jsonb`, `rapor_kurmer.attendance_jsonb`, `rapor_kurmer.kepsek_id`, `rapor_kurmer.semester_id`

   Kalau kolom belum ada → query 500. Cek schema rapor_kurmer (migration 053) dan tambah kolom missing kalau perlu, atau ganti `COALESCE` ke literal default.

2. **`payment_handlers.rs`** — `sqlx::types::BigDecimal` butuh feature flag `bigdecimal` di sqlx crate. Kalau cargo error, ganti type ke `f64` atau pakai `decimal` feature.

3. **`get_parent_invoices()` RPC** pakai `auth.uid()` — pastikan ekstensi/fungsi `auth.uid()` ada di DB (Supabase pattern; di stack VIL native mungkin namanya beda — cek `edusync-api/schema/baseline.sql`).

4. **InvoiceList.tsx** — mengasumsikan `db.rpc` ada di VIL client. Kalau VIL client masih PostgREST-style ini OK; kalau bukan, swap ke fetch langsung ke `/api/v1/data/get_parent_invoices`.

5. **A2 RBAC matrix** — endpoint paths di `tests/e2e/rbac.spec.ts` mungkin tidak match policy.yaml (saya nulis berdasarkan asumsi). Run sekali, lihat `.qa-rbac/matrix.json`, sesuaikan policy atau test list. Yang penting: jangan flip enforce sebelum `unexpected_deny = 0`.

6. **`rbac_scope.rs`** — saya tambahkan ke `lib.rs` tapi belum dipakai handler manapun. Modul ini standalone shadow tool; A3 yang akan wire ke middleware.
